# KERNEL `v0.1.0-alpha`

Свободный мессенджер со сквозным шифрованием, который разворачивается на своём сервере.
**Альфа: личные переписки, шифрование и реакции работают, но API и формат данных ещё будут меняться.**

> Скачал, развернул, общаешься. Без рекламы, без слежки, без лишнего.

## 🔐 Шифрование

Сообщения шифруются **в браузере**. Сервер хранит только шифротекст и не может прочитать
переписку — у него нет ключей.

- **Пароль не уходит на сервер.** Браузер выводит из него мастер-ключ
  (PBKDF2-SHA256, 210 000 итераций, случайная соль), а из мастер-ключа —
  два независимых значения: `auth hash` (отправляется на сервер для входа)
  и ключ шифрования ключа `KEK` (остаётся в браузере). Сервер хранит только
  scrypt-хеш от `auth hash` — сам пароль он не видит.
- **Ключи переписки.** У каждого аккаунта своя пара ECDH P-256. Приватный ключ
  лежит на сервере **завёрнутым** в AES-GCM под `KEK`, поэтому развернуть его
  можно только зная пароль. Публичный ключ открыт — он нужен собеседникам.
- **Сообщения и реакции** шифруются AES-GCM на общем ключе, который обе стороны
  выводят из ECDH-секрета (HKDF-SHA256). У каждого сообщения свой случайный nonce.
- **Старые сообщения.** Строки, записанные до появления шифрования, лежат открытым
  текстом. Как только участник открывает переписку, браузер перешифровывает их
  на месте, и в базе остаётся только шифротекст.

Что видит сервер: кто с кем переписывается, когда и какого размера сообщения,
сколько реакций. Текста он не видит.

> **Нужен HTTPS.** Браузеры дают доступ к Web Crypto только в защищённом контексте
> (HTTPS или `localhost`). По обычному HTTP мессенджер откажется отправлять сообщения
> и покажет «шифрование недоступно».

## 💬 Что умеет прямо сейчас

- **Регистрация и вход** по нику и паролю. Ник 3–20 символов: латиница, цифры, `_`,
  пароль от 6 символов.
- **Личные переписки один на один.** Текст до 4000 символов, история сохраняется.
- **Реакции на сообщения.** Одна реакция на человека на сообщение, эмодзи тоже
  шифруются. Набор: 👍 ❤️ 😂 🔥 😮 😢 🐱 🐋
- **Поиск людей** по нику — прямо в строке слева.
- **Список чатов** с последним сообщением; превью расшифровывается в браузере.
- **Профиль:** «о себе» до 200 символов, адрес до 100, анонимный номер вида
  `+888 0001-19`, который считается из ID пользователя.
- **Настройки:** смена пароля (с переупаковкой ключа) и удаление всей истории.

## 🎨 Оформление

- **66 градиентных тем** в 17 цветовых семействах — от почти чёрных до кремово-белых.
- **Конструктор своей темы:** тип градиента (линейный, радиальный, конический), угол 0–360°,
  от 2 до 6 цветовых стопов с пипеткой и HEX-полем, кнопка «Рандом».
- **Свои темы хранятся в аккаунте** — до 60 штук, доступны с любого устройства.
- **Интерфейс подстраивается под тему:** по яркости градиента сам переключается на светлый
  или тёмный набор элементов. 49 из 66 тем светлые — с жёстко белым текстом они были нечитаемы.
- **Подпись на карточке темы** выбирается отдельно для каждой карточки; если градиент не даёт
  нужного контраста, под текстом появляется подложка.
- **Переключатель плавных переходов** в настройках чата — анимации включены по умолчанию
  и не зависят от системной настройки «уменьшить движение».

## 🖥 Как выглядит

Слева — список чатов и поиск, справа — переписка, профиль или настройки.
Вход — форма логина и заготовка под QR-код. Всё на чистом HTML, CSS и JavaScript,
без фреймворков и сборщиков; шрифт JetBrains Mono.

## 🚀 Запуск

### Локально

```bash
git clone https://github.com/factsaime/KERNEL-2.git
cd KERNEL-2
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
python app.py
```

Откроется на `http://127.0.0.1:5050` (порт меняется переменной `PORT`).
`localhost` считается защищённым контекстом, поэтому шифрование работает сразу.
База `kernel.db` и ключ `.secret_key` создаются сами и в репозиторий не попадают.

### На сервере

Скопировать проект в `/opt/kernel`. Для шифрования нужен HTTPS:

```bash
# свой сертификат
TLS_CERT=/etc/letsencrypt/live/example.com/fullchain.pem \
TLS_KEY=/etc/letsencrypt/live/example.com/privkey.pem \
PUBLIC_PORT=8443 bash /opt/kernel/deploy/deploy.sh

# или самоподписанный, если сертификата нет
SELF_SIGNED=1 PUBLIC_PORT=8443 bash /opt/kernel/deploy/deploy.sh
```

Скрипт поднимает `gunicorn` на localhost и сайт в nginx, плюс systemd-сервис `kernel`.
Когда включён TLS, сервис получает `KERNEL_SECURE_COOKIE=1`, и cookie сессии
не уходит по открытому каналу. Без сертификата сайт поднимется, но шифрование
в браузере будет недоступно — скрипт об этом предупредит.

## 🔌 API

Все ответы — JSON. Для не-GET запросов нужен заголовок `X-Requested-With: kernel`
(защита от межсайтовых запросов), для всего кроме входа и регистрации — активная сессия.

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/auth/params?username=` | соль и схема входа для ника |
| `POST` | `/api/register` | создать аккаунт (auth hash + публичный ключ + завёрнутый приватный) |
| `POST` | `/api/login` | вход по auth hash (старые аккаунты — по паролю, с апгрейдом) |
| `POST` | `/api/crypto/setup` | записать или переупаковать свои ключи |
| `GET` | `/api/crypto/key` | свой завёрнутый приватный ключ |
| `POST` | `/api/logout` | выйти |
| `GET` | `/api/me` | свой профиль (без приватного ключа) |
| `POST` | `/api/profile` | сохранить «о себе» и адрес |
| `GET` | `/api/users?q=` | поиск людей по нику, вместе с их публичными ключами |
| `GET` | `/api/chats` | список чатов с последним сообщением |
| `GET` | `/api/messages/<id>?after=` | переписка (до 500 за раз) + публичный ключ собеседника |
| `POST` | `/api/messages/<id>` | отправить сообщение; **открытый текст отклоняется** |
| `POST` | `/api/messages/reencrypt` | перешифровать старые строки на месте |
| `GET` | `/api/reactions?ids=` | реакции для сообщений |
| `POST` | `/api/messages/<id>/reaction` | поставить или убрать свою реакцию |
| `GET` | `/api/themes` | свои темы |
| `POST` | `/api/themes` | сохранить список своих тем |
| `POST` | `/api/settings/password` | сменить пароль (с переупаковкой ключа) |
| `POST` | `/api/settings/clear` | удалить всю свою историю |

## 🛠 Чего ещё нет

- **Нет forward secrecy.** Ключ переписки выводится из долговременных ключей, поэтому
  украденный приватный ключ вместе с паролем открывает всю историю, включая прошлую.
- **Забытый пароль = потерянная история.** Восстановления пароля нет, а ключ завёрнут
  именно в пароль — расшифровать переписку после сброса будет нечем.
- **Метаданные видны серверу:** кто с кем, когда, размер сообщений, число реакций.
- **Один ключ на аккаунт, а не на устройство.** Отдельных ключей под каждое устройство
  и подтверждения новых устройств нет.
- **Доверие к загрузке.** Сервер отдаёт клиентский JS, поэтому вредоносный сервер
  теоретически может подсунуть код, который сольёт ключи. Защиты от подмены сборки нет.
- **Старые сообщения шифруются не сразу**, а при первом открытии переписки кем-то из участников.
- **Только личные чаты.** Групп, каналов, пересылки нет.
- **Только текст.** Ни картинок, ни файлов, ни голосовых.
- **«QR-код» на экране входа — заглушка.**
- **Нет уведомлений, статуса «прочитано» и «печатает».**
- **Обновления приходят опросом сервера:** сообщения каждые 1.5 с, список чатов каждые 4 с.
  WebSocket не используется, поэтому при большом числе людей будет тяжело.
- **Нет модерации, блокировок и жалоб.** Кто угодно может завести аккаунт и написать вам.

Чтобы фиксировать этапы разработки. Сначала это был мессенджер с шестью темами,
